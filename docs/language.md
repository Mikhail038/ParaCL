## 0. Категории поведения

Для каждой программы (или конструкции в ней) определено, к какой категории она
относится:

| Категория | Что происходит | Аналог в C/C++ |
|---|---|---|
| **well-formed** | программа корректна и исполняется | — |
| **ill-formed** | компилятор отвергает программу с диагностикой, до запуска | ошибка компиляции |
| **runtime error** | программа корректна, но при исполнении останавливается с сообщением и ненулевым кодом возврата | `std::terminate`, исключение без обработчика |
| **UB** (undefined behavior) | поведение не определено, может произойти что угодно | `INT_MAX + 1`, выход за границы массива |

### 0.1. Принцип «в ParaCL нет UB»

**Статус:** предложено

Каждая ситуация либо ill-formed, либо runtime error, либо определена. Спека делает
так для целых чисел («arithmetic wraps around on overflow — there is no undefined
behavior»); предлагается распространить это на весь язык.

Следствие для LLVM IR: в самом LLVM UB много (деление на ноль в `sdiv`, чтение за
границами массива). Генератор IR должен сам вставлять проверки перед такими
инструкциями.

### 0.2. Что считается runtime error

**Статус:** открыто

Кандидаты:

- [ ] выход индекса за границы массива;
- [ ] целочисленное деление на ноль, `INT_MIN / -1`;
- [ ] ввод не разбирается как значение нужного типа (`input(0) : int`, а на входе `abc`);
- [ ] ввод закончился (EOF).

## 1. Лексика и синтаксис

### 1.1. `while`

**Статус:** принято

**Вопрос.** `while` используется в примерах (раздел 1.9), но отсутствует в списке
ключевых слов (раздел 1.1).

**Решение.** `while` — ключевое слово, наравне с перечисленными в разделе 1.1.

**Обоснование.** Конструкция описана в спеке и используется в примере; отсутствие
в списке считаем опечаткой. Использовать `while` как идентификатор нельзя.

### 1.2. Набор операторов и их приоритеты

**Статус:** открыто

**Вопрос.** Спека нигде не перечисляет операторы. В примерах встречаются
`+ - * < > ==`, а `/`, `%`, `!=`, `<=`, `>=`, `&&`, `||`, `!`, унарный минус не
упоминаются. Приоритеты и ассоциативность тоже не заданы.

**Вариант.** Взять набор и приоритеты из C, без побитовых операций и присваивания
в выражениях.

## 2. Типы и преобразования

### 2.1. Тип целочисленного литерала в выражении

**Статус:** открыто

```pcl
v2 : int(16) = 5;
v3 = v2 + 1;          // int(16) или int(32)?
```

**Варианты.**
- Литерал подстраивается под тип второго операнда (`int(16)`).
- Литерал всегда `int(32)`, и действуют правила расширения, как integer promotion в C.

### 2.2. Смешанные типы и сужающие преобразования

**Статус:** открыто

```pcl
v1 : double = v0;                      // int → double неявно (пример из спеки)
f3 : (x : int, y : double) : int = { v3 = x + y; v3 * v3; };
```

**Вопрос.** В `f3` выражение `x + y` имеет тип `double`, а функция возвращает
`int`. Значит, спека неявно допускает сужение `double → int`. Нужны общие правила:
- `int(N) + int(M)` — какой тип результата?
- `int + double` → `double`?
- Какие неявные преобразования разрешены, а какие ill-formed?
- Как работает `char` (raw byte, как `std::byte`): разрешена ли арифметика с ним?

### 2.3. Объявление без инициализации

**Статус:** открыто

```pcl
v3 : int;
output(0, v3);        // что выводится?
```

**Варианты.** Инициализация нулём; чтение до присваивания — ill-formed; чтение до
присваивания — runtime error.

### 2.4. `float` и `double`

**Статус:** открыто

**Вопрос.** `float` есть в списке ключевых слов, но нигде не описан. Вероятно,
`float` — 32 бита, `double` — 64 бита (IEEE 754), как в C. Нужно также решить,
какие преобразования между ними неявные.

### 2.5. Тип условия в `if` / `while`

**Статус:** открыто

```pcl
if (v1) ...           // v1 : double — допустимо?
while (arr0) ...      // массив — ill-formed?
```

**Вопрос.** Спека говорит «while a condition remains true (non-zero)». Каким типом
может быть условие: любой целый, любой числовой или только результат сравнения?
Какой тип у результата сравнения `a < b`?

## 3. Имена и области видимости

### 3.1. Присваивание внешней переменной внутри функции

**Статус:** открыто

```pcl
v3 = 10;
f0 = { v3 = input(0) + 1; v3 * v3; };
v7 = f0(2);
output(0, v3);        // 10 или 3?
```

**Вопрос.** Спека: «every entity is introduced upon its first mention». Если `v3`
уже есть снаружи, `v3 = ...` в теле функции создаёт локальную переменную или
меняет внешнюю?

**Варианты.**
- Функция видит внешние переменные и меняет их, как глобальные переменные в C.
- Тело функции — изолированная область, все имена в нём локальные.
- Функция видит внешние переменные только на чтение.

### 3.2. Самоссылка в инициализаторе

**Статус:** открыто

```pcl
s3 : { x : int, g : () } = glue(v0, bind(f1, s3.x));
```

**Вопрос.** `s3` упоминается в собственном инициализаторе. Это ill-formed или
`bind` захватывает ссылку на поле будущей структуры (как `this` в C++)?

### 3.3. Области видимости блоков `if` / `while` / `for`

**Статус:** открыто

```pcl
if (v0 == 0) {
  t = 5;              // первое упоминание t
}
output(0, t);         // t видна здесь?

for (x in 0:5) { ... }
output(0, x);         // а x?
```

**Варианты.**
- Каждый `{ ... }` — своя область видимости, как в C.
- Блоки управляющих конструкций не создают областей, как в Python.

Если `t` видна после `if`, а ветка не выполнилась, встаёт вопрос из 2.3: какое
у `t` значение?

### 3.4. Несколько единиц трансляции

**Статус:** открыто

**Вопрос.** Спека: «Every program consists of one or more translation units».
При этом не сказано:
- как компилятор получает несколько файлов (несколько аргументов командной строки?);
- в каком порядке они исполняются;
- видны ли сущности одного файла в другом.

**Вариант.** Для начала поддерживать один файл и явно задокументировать это
ограничение.

## 4. Функции

### 4.1. `input` внутри функции

**Статус:** открыто

**Вопрос.** На верхнем уровне `input(0)` читает поток ввода номер 0. Внутри
функции `input(0)` — аргумент номер 0. Отсюда несколько вопросов:

1. **Число параметров.** У `f0 = { v3 = input(0) + 1; v3 * v3; };` один
   параметр, потому что максимальный индекс равен 0. А если в теле только
   `input(2)`, функция принимает 3 аргумента (два не используются) или это ill-formed?
2. **Константность индекса.** `input(i)` с переменной `i` внутри функции — ill-formed?
3. **Именованные параметры и `input`.** В `f1 : (x) = ...` выражение `input(0)` —
   то же, что `x`? Или смешивать запрещено?
4. **Чтение stdin из функции.** Если `input` внутри функции всегда означает
   аргумент, функция не может читать ввод. Это намеренное ограничение?

### 4.2. Число аргументов у `bind`

**Статус:** открыто

```pcl
s4 : { x : int, g : () } = glue(v0, bind(f2, s4.x));
v9 = s4.g(v1);        // эквивалентно f2(s4.x, v1)
```

**Вопрос.** Тип `g` объявлен как `()` (без параметров), но вызывается с одним
аргументом. Варианты:
- `()` в типе поля означает «какая-то функция», без проверки числа параметров.
- В спеке опечатка, правильно `g : (y)`.

### 4.3. Рекурсивная generic-функция

**Статус:** открыто

```pcl
f4 : (x) = { if (x < 2) return 1; x * f4(x - 1); };
```

**Вопрос.** Как определяется тип возврата? Есть `return 1` (`int`) и
`x * f4(x - 1)`, тип которого зависит от самой `f4`. Вариант: тип возврата
выводится из нерекурсивных `return`, а рекурсивный вызов проверяется против него.
Как это реализовать — см. [decisions.md](decisions.md), решение 4.

### 4.4. `{` в позиции выражения

**Статус:** открыто

```pcl
arr1 : int[5] = {1, 2, 3, 4};               // инициализатор массива
f0 = { v3 = input(0) + 1; v3 * v3; };      // литерал функции
x = {5};                                    // ?
y = { 5; };                                 // ?
```

**Вопрос.** Как различать? Вариант: выражения через запятую без `;` —
инициализатор, инструкции через `;` — тело функции.

### 4.5. Функции как значения

**Статус:** открыто

```pcl
f8 : (x : int) = x + 1;
f9 : (x : int) = x * x + 1;
f8 = f9;              // valid по спеке
f5 = f4;              // invalid: generic
```

**Вопрос.** Раз функции можно присваивать, они — значения (как указатели на
функции в C). Отсюда:
- Совместимы ли `(x : int)` и `(y : int)` — важны ли имена параметров?
- Совместимы ли функции с разным возвращаемым типом?
- Можно ли передать функцию аргументом в другую функцию, вернуть из функции,
  положить в массив?
- Почему присваивание generic-функций invalid — потому что у них нет одного
  конкретного типа? Тогда что с `g = f4;`, где `g` новая переменная?

### 4.6. `return` вне функции

**Статус:** открыто

```pcl
v0 = 5;
return v0;            // на верхнем уровне
```

**Варианты.** Ill-formed или завершение программы (с кодом возврата?).

## 5. Массивы и структуры

### 5.1. Неполный инициализатор

**Статус:** открыто

```pcl
arr1 : int[5] = {1, 2, 3, 4};      // 4 значения на 5 элементов
```

**Варианты.** Остаток заполняется нулями (как в C) или ill-formed.

### 5.2. Синтаксис диапазонов

**Статус:** открыто

```pcl
arr_inputs = input(0..3) : int[4];
for (x in 0:5) ...
for (x in 0:5:1) ...
```

**Вопрос.** Два синтаксиса диапазонов: `..` и `:`. Это разные конструкции или
одна? Включается ли правая граница? `0..3` даёт 4 элемента (включительно), `0:5`
в цикле, видимо, — 5 итераций (не включительно).

### 5.3. `input(0..3)` — что именно читается

**Статус:** открыто

**Варианты.**
- Четыре значения из потока 0.
- По одному значению из потоков 0, 1, 2, 3.
- Внутри функции — аргументы 0–3.

### 5.4. Присваивание массивов и структур: копия или ссылка

**Статус:** открыто

```pcl
a : int[3] = {1, 2, 3};
b = a;
b[0] = 100;
output(0, a[0]);      // 1 или 100?

for (x in a) { x = 0; }   // меняет ли это a?
```

**Вопрос.** Спека говорит, что массивы лежат на стеке, — это намекает на
копирование, как у `struct` в C. Но это нигде не сказано явно, ни для массивов,
ни для структур, ни для переменной цикла `for (x in a)`.

## 6. Ввод и вывод

### 6.1. Номера потоков

**Статус:** открыто

**Вопрос.** Все примеры используют поток 0. Что такое `input(1)` и `output(1, v)`
на верхнем уровне — stderr, отдельный файл, ill-formed?

### 6.2. Формат вывода

**Статус:** открыто

**Вопрос.** Как печатается значение каждого типа:
- `double` — сколько знаков, `1` или `1.0`?
- `char` — как число или как символ?
- Массив, структуру, функцию — можно ли вообще передать в `output`?
- Разделитель между выводами — перевод строки?

От ответа зависит формат эталонных `.out` файлов в тестах.
